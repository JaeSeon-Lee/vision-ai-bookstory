난수 3회 평균이다.

1차의 "빈 스크린 배경"은 영상 전체에서 추정한 것이라 **손 그림자가 희미하게 남아 있다.** 어두운 곳은 다섯 영상 모두에 남아 있고 새가 가장 진하다(배경이 최대 10% 어둡다). 밝은 곳은 새에서 눈에 띈다(최대 2.7%). 그림 01~05·07~11, `images/`, 1차 CSV 3개가 이 배경을 쓴다. 새 인식기(그림 12~15)는 빈 프레임으로 배경을 만들어 이 문제가 없다.

깨끗한 배경으로 다시 재면 다음과 같다(난수 첫 회, 시험 프레임 2,222장). 차이가 작아 표의 수치는 1차 방식 그대로 두었다. **다만 동작 하나 빼기에서 SVM과 랜덤포레스트의 순위가 뒤집히므로, 1차에서 어느 쪽이 낫다고 말하지 않는다.**

| 검증 방식 (난수 첫 회) | SVM 1차 그대로 → 깨끗한 배경 | 랜덤포레스트 1차 그대로 → 깨끗한 배경 |
|---|---:|---:|
| 동작 하나 빼기 | 90.1% → 91.5% | 90.9% → 89.7% |
| 밝음 → 어두움 | 90.2% → 90.2% | 90.4% → 89.8% |
| 어두움 → 밝음 | 75.7% → 75.2% | 79.0% → 78.9% |

### 3. 새 인식기로 교체

1차 인식기는 앱에서 빈 화면을 달로 답하는 등 문제가 있었다. "가장 진한 곳을 1로" 맞추는 방식이 잡음까지 키웠고, "다섯 가지가 아닌 모양"을 따로 배우지 않았으며(확률이 낮을 때만 답을 보류), 조명 기울기와 카메라 움직임에 약했다.

| 바꾼 점 | 1차 | 새 인식기 |
|---|---|---|
| 조명 | 화면 전체 밝기만 보정 | 기울어진 조명(평면)까지 빼고 비교 |
| 그림자 여부 | 진하기와 최소 크기(50픽셀)로 판정 | 진하기, 스크린 대비 면적(4~75%), 윤곽 선명도를 모두 통과해야 함 |
| 특징 | 명암이 있는 조각의 윤곽 방향(HOG)과 Hu 모멘트 등 | 흑백 윤곽의 HOG |
| 답의 종류 | 다섯 가지. 확률이 낮으면 보류 | 다섯 가지 + 따로 학습한 "없음" |
| 달 | 분류기에 맡김 | 원형도 0.82 이상이면 분류기 없이 달, 분류기가 달이라 해도 0.70 미만이면 "없음" |
| 배경 | 찍은 것 그대로 | 그림자가 없거나 아주 작거나 윤곽이 흐린 화면이면 프레임마다 3%씩 적응 |

지금 앱의 인식 과정:

1. 빈 스크린 12프레임으로 배경을 만들고, Otsu로 밝은 스크린을 찾는다.
2. 폭 480의 흑백 화면에서 조명 기울기를 빼고 배경보다 어두운 곳을 그림자 윤곽으로 자른다.
3. 진하기·면적·선명도를 통과하면 윤곽을 64×64에 맞춰 HOG 1,764개를 뽑는다.
4. 달은 원형도로 먼저 가리고, 나머지는 PCA 150차원과 SVM으로 여섯 가지(다섯 + 없음) 중에 고른다.
5. 최근 8프레임 중 6번 이상 같은 답이면 인정하고, 장면이 요구하는 그림자일 때만 진행한다.

학습 데이터는 다섯 그림자 각 1,000장과 없음 1,500장, 모두 6,500장이다. 영상에 교란을 넣어 뽑은 윤곽을 좌우 반전·회전·크기·기울기·팔 길이·윤곽 번짐을 바꿔 늘렸다. 없음은 얼룩, 팔뚝, 주먹, 편 손, 다각형, 손의 일부 같은 모양을 합성했다.

| 그림 | 말할 요점 |
|---|---|
| 12_기존과_새_방식_비교 | **학습에 쓴 녹화 영상에 교란을 합성한 예시**이며 실제 웹캠이 아니다. 같은 교란 화면에서 기존 방식은 빈 스크린을 토끼로, 새 방식은 "없음"으로 답한다 |
| 13_기존과_새_방식_정확도 | 심한 교란에서 45.4% → 94.7%, 빈 화면 오인은 93.0% → 0% |
| 14_혼동행렬_새_방식 | 새 방식은 틀리더라도 다른 동물(0.5%)보다 "없음"(3.4%)으로 놓친다 |
| 15_동물별_정답률_새_방식 | 새 88%, 달 94%가 상대적으로 낮다 |

| 동작 하나 빼기 | 기존 방식 | 새 방식 SVM (앱) | 새 방식 랜덤포레스트 |
|---|---:|---:|---:|
| 교란 없음 | 90.0% | **97.1%** | 92.5% |
| 약한 교란 | 82.3% | **96.4%** | 92.4% |
| 심한 교란 | 45.4% | **94.7%** | 90.5% |
| 합계 | 72.6% | **96.0%** | 91.8% |
| 다른 동물로 오답 | 26.9% | **0.5%** | 2.0% |
| 빈 화면 오인 (143장 × 3) | 171 | **0** | **0** |
| 손이 들어오고 나갈 때 다른 동물로 오답 (434장 × 3) | 704 | **40** | 62 |

합계의 장수는 같은 프레임을 교란 3종으로 세 번 센 것이다. 동작별로 보면 새 방식 SVM이 가장 약한 것은 밝은 곳 새로, 75%다.

교란은 잡음, 흐림, 노출, 조명 기울기, 카메라 이동을 **합성**한 것이다. 새 방식은 같은 종류의 교란을 넣어 학습했고 기존 방식은 그러지 않았으므로, 이 표는 분류기만의 비교가 아니라 두 방식 전체의 비교다.

- 15:10 기록에서는 스크린 앞 맨손을 여우 37프레임, 사슴 43프레임으로 답했다. 실제 그림자인지는 구별하지 못하므로 사슴이 인식됐다는 근거로 쓰면 안 된다. 달은 기다리기만 하고 그림자를 비추지 않았다.

## 예상 질문과 한계

1. **왜 96%가 아니라 80%인가?** 학습 영상과 실제 공연은 조명, 손 크기와 위치가 다르다. 실제 기록은 시연 한 번뿐이라 80.1%도 어림값이다.
2. **데이터가 적다.** 영상에는 서로 다른 동작이 19개뿐이고 새는 조명마다 1개다.
3. **96.0%도 낙관적일 수 있다.** 달의 원형도 같은 기준값은 시험에 쓴 영상을 보고 정한 것이라, 학습에서 뺀 동작도 기준값에는 영향을 주었을 수 있다.
4. **영상의 정답은 자동으로 붙였다.** 영상 이름을 정답으로 삼아 잡음이 조금 섞였다. 실제 웹캠의 정답은 당시 저장한 프레임을 보고 구간으로 붙였다(`tools/live_eval.py`의 `LABELS`). 원본은 지웠으므로 다시 채점할 수 없다.
5. **Otsu를 어디에 쓰나?** 배경에서 밝은 스크린을 찾을 때만 쓴다. 그림자 분리의 Otsu는 비교 실험이다.
6. **스크린이 있는지 확인하지 않는다.** 스크린이 없어도 가장 밝은 덩어리를 스크린으로 여긴다.

### 시연 전 확인

- 스크린 뒤의 조명을 켜고 테두리가 화면에 다 들어오게 카메라를 고정한다.
- 손을 치우고 C로 웹캠을 켠다. 켜지면 1초쯤 뒤 배경을 자동으로 찍는다. 카메라나 조명을 움직였으면 손을 치우고 B로 다시 찍는다.
- D로 진단 화면을 켜서 초록 테두리가 스크린과 맞는지, 주황색이 그림자와 맞는지 본다.
- 손은 스크린 뒤에서, 그림자가 테두리 안에 다 들어오게 비춘다.
- 인식이 안 될 때는 1~5 키(새·토끼·여우·사슴·달)로 그림자를 대신하거나 → 키로 다음 장면으로 넘어간다.
